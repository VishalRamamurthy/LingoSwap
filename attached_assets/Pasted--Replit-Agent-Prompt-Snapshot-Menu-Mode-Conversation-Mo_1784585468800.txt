## 2. Feature A — Snapshot: Text mode vs Menu mode

### 2a. Mode selector

- Add a segmented control at the top of the Snapshot screen: **Text | Menu**, defaulting to Text.
- Selecting the mode **before** capture is the primary flow, because the mode changes the OCR request parameters.
- After a result is shown, the user can switch modes to re-analyze **the same photo** without re-shooting it. This costs one additional OCR call — show a brief inline note ("Re-reading as a menu…") so it isn't silent.
- Persist the last-used mode with AsyncStorage so it survives app restarts.

### 2b. What changes in the OCR call

Menu mode uses the **same OCR.space endpoint and the same key** — only the parameters change:

| Parameter | Text mode | Menu mode | Why |
|---|---|---|---|
| `isTable` | `false` | **`true`** | OCR.space explicitly recommends this for menus, receipts, and table-like layouts; it forces line-by-line output instead of a reflowed blob |
| `isOverlayRequired` | `false` | **`true`** | returns per-word `Left`/`Top`/`Width`/`Height` boxes, which we use for line grouping and price-column detection |
| `OCREngine` | 2 (fallback 3) | 2 (fallback 3) | unchanged |
| `scale` / `detectOrientation` | `true` | `true` | unchanged |

Note: overlay data adds negligible cost on Engine 2, but makes Engine 3 calls 2–3× slower. If you fall back to Engine 3 in menu mode, that's acceptable, but log the slower path.

### 2c. Server-side menu segmentation

Write a **pure, exported, testable function** — no network calls inside it — that turns an OCR response into structured items:

```ts
type MenuItem = {
  id: string;
  originalText: string;      // the dish name / description, price stripped
  price: string | null;      // verbatim, e.g. "12,50 €" — NEVER translated or reformatted
  translatedText: string;    // filled in later
  isSectionHeader: boolean;  // "Antipasti", "Desserts"
};
```

Segmentation rules:

1. **Group words into lines** using the overlay's `Top` and `MaxHeight` values (words within roughly one line-height of each other belong to the same line). Fall back to splitting `ParsedText` on newlines if overlay data is missing.
2. **Detect and strip prices** with a regex covering: leading or trailing currency symbols (`$ € £ ¥ ₩ ₹ ฿ zł kr`), 3-letter codes (`USD`, `EUR`), both decimal separators (`12.50` and `12,50`), and thousands separators. Store the price string **exactly as it appeared**. Prices are passed through verbatim — never sent to translation, never reformatted, never currency-converted.
3. **Detect section headers**: short lines, no price, often ALL CAPS or visually larger (compare `MaxHeight` against the median line height from the overlay).
4. **Merge continuation lines**: a line with no price that sits directly under a priced line and starts lowercase is usually a description — merge it into the previous item rather than creating a new one.
5. **Drop noise**: lines that are only punctuation, dot leaders (`. . . . .`), or fewer than 2 characters.

### 2d. Batch translation — this is the efficiency requirement

**Translating N menu items must cost exactly ONE translation request, not N.**

- If the existing translation service accepts an array, use it directly.
- If it only accepts a single string, join the items into one numbered payload:
  ```
  1. Spaghetti alla Carbonara
  2. Insalata Mista
  3. Tiramisù
  ```
  and instruct the model to return the same numbering with one translation per line and nothing else.
- **Validate the response**: the returned line count must equal the sent count and the numbering must be intact. On mismatch, retry once; if it still mismatches, fall back to per-item translation and log a warning. Never silently misalign a translation with the wrong dish — that's the worst possible failure for this feature.
- Section headers get translated too, in the same batch.
- Cap at 60 items per request; chunk beyond that and reassemble in order.

### 2e. Menu mode UI

- Photo at the top, as in Text mode.
- Below it, a **list** — not a blob. Each row: translated name as the primary line, original name smaller and dimmer beneath it, price right-aligned and visually distinct.
- Section headers render as list section headings.
- Tapping a row expands it: full original, full translation, copy button, and a speak button (see Feature B's TTS helper — reuse it, don't write a second one).
- Changing the target language re-translates from the **cached original items** — it must not re-run OCR.
- Empty state: if segmentation yields fewer than 2 items, show "This doesn't look like a menu" and offer a one-tap switch to Text mode using the same photo.

## 3. Feature B — Conversation mode

### 3a. Where it lives

Put it **inside the existing Translate tab** as a mode toggle (e.g. a segmented control: **Text | Voice | Conversation**), not as a new tab. Reason: iOS collapses a tab bar into "More" past 5 items, and conversation mode is a *way of translating* rather than a separate destination. Report the current tab count in discovery; if you disagree after seeing the code, say so before building.

### 3b. Layout

A split screen with two halves facing opposite directions:

- **Top half rotated 180°** for the person across from you, showing their language.
- **Bottom half** upright, showing your language.
- Each half has one large tap-to-talk button and a transcript area.
- Language selectors: yours and theirs, each reusing the existing picker component.
- The active half is visually emphasized; the inactive half dims.
- A shared, scrollable transcript of the exchange sits between them, newest at the bottom, each entry showing both the original and the translation.

### 3c. Turn flow

Implement as an explicit state machine — no ad-hoc booleans:

```
idle → recording(side) → transcribing → translating → speaking → idle
```

Each turn:
1. User taps their side's button → record with `expo-av`, using the **exact same recording configuration the existing STT feature uses**. Do not invent new audio settings.
2. Tap again (or auto-stop on silence, if you implement it) → stop recording.
3. Upload to the **existing transcription route**. Do not create a new one.
4. Translate the transcript into the other side's language via the **existing translation service**.
5. Speak the translation with `expo-speech`, using the target language code so iOS picks the right voice.
6. Append both texts to the transcript and return to idle.

### 3d. The audio-session gotcha — do not skip this

On iOS, `expo-av` recording and audio playback need different audio modes. **If you leave `allowsRecordingIOS: true` set while trying to play speech, playback is silent or routes to the earpiece instead of the speaker.** This is the single most common way this feature ships broken.

Set the mode explicitly at each transition:

- Before recording: `allowsRecordingIOS: true`
- Before speaking: `allowsRecordingIOS: false`, `playsInSilentModeIOS: true`
- Verify audio comes out of the **speaker** at a normal volume, not the earpiece.

Test this on the device with the ringer switch **off/silent** — that's exactly the condition `playsInSilentModeIOS` exists to handle, and it's how most people carry their phone.

### 3e. Required cleanup and safety

- Stop and unload any active recording when the screen loses focus, the app backgrounds, or the component unmounts. A mic left hot is a real bug, not a nitpick.
- Delete temporary audio files after successful upload (`expo-file-system`). Without this you leak files onto the user's device on every single turn.
- Stop any in-flight speech before starting a new recording, so the app never listens to itself.
- Guard against double-taps and against tapping the other side's button mid-turn.
- Handle: mic permission denied, no speech detected, network failure mid-turn (keep the transcript, show a retry on that entry only), and very long recordings (cap at ~60s with a visible timer).

### 3f. Efficiency requirements

- Identical `(text, sourceLang, targetLang)` must not be re-translated — memoize within the session.
- Swapping the two languages must reuse existing transcript data rather than re-translating everything.
- No polling, no timers left running, no re-render of the whole transcript on each keystroke or state tick.
