## 2. Architecture — implement it this way

```
[Phone / Expo Go]                          [artifacts/api-server]
 expo-image-picker  ──capture──►
 expo-image-manipulator ──resize+compress──►
        │
        └── POST /api/snapshot/translate ──►  1. validate + size check
                                              2. OCR provider → detected text
                                              3. existing translation service
                                              4. return JSON
        ◄── { detectedText, sourceLanguage, translatedText, targetLanguage }
```

Rationale (so you don't "optimize" this away): this mirrors the app's existing audio → backend → transcript pattern, keeps all provider keys server-side, and requires zero native modules, which is what makes it work in Expo Go.

## 4. Backend work (`artifacts/api-server`)

Create one new endpoint, following the existing route conventions you found in the discovery step:

**`POST /api/snapshot/translate`**

Request body (JSON):
```ts
{
  image: string;            // base64, no data: prefix
  mimeType: 'image/jpeg';
  targetLanguage: string;   // reuse the app's existing language code type
  sourceLanguage?: string;  // omit or 'auto' for detection
}
```

Response (200):
```ts
{
  detectedText: string;         // '' if nothing found
  detectedLanguage?: string;    // best-effort
  translatedText: string;       // '' if detectedText is ''
  targetLanguage: string;
  reason?: 'no_text_found' | 'low_confidence';
}
```

Implementation requirements:

1. **Validate with zod** (match the existing validation pattern). Reject payloads over ~8 MB with a clear 413.
2. **OCR provider selection.** Check what vision-capable credentials already exist in Replit Secrets and prefer reusing the provider the app already pays for. Preference order:
   - (a) The same LLM provider already used elsewhere in the app, via its vision model. Prompt it strictly: transcribe all visible text verbatim, preserve line breaks and reading order, return only the text with no commentary, and return an empty string if no legible text is present.
   - (b) Google Cloud Vision `TEXT_DETECTION` if a key for it exists.
   
   Put the choice behind an `OCR_PROVIDER` env var with a sensible default so it can be swapped without a code change. Report which provider you selected and which secret name it expects — I'll add the key if it's missing.
3. **Translate using the app's existing translation service/function.** Do not call a translation API directly from this new route if a service layer already exists.
4. If OCR returns nothing, return **200** with `detectedText: ''` and `reason: 'no_text_found'` — not an error status. The client shows a friendly empty state.
5. Set a request timeout around 30s, return the app's standard structured error shape on failure, and never leak provider error text containing keys.
6. If text is very long, chunk it for translation and reassemble in order rather than truncating silently.

## 5. Frontend work (`artifacts/translator`)

### 5a. The new tab

- Create the route file (e.g. `app/(tabs)/snapshot.tsx` — match the actual folder structure you found).
- Register it in the tabs layout with title **"Snapshot"**, placed **immediately after the Translate tab and before History**, so the order reads: Translate · Snapshot · History · Profile.
- Use the same icon library the other tabs use (`expo-symbols` or `@expo/vector-icons`), with an icon that reads as "camera on text" — e.g. SF Symbol `camera.viewfinder` or `text.viewfinder`, or Ionicons `scan-outline`. Match the existing tabs' icon size and focused/unfocused colors from `constants/` — do not hardcode new color values.

### 5b. Screen states

Build the screen as an explicit state machine: `idle → captured → processing → result → error`.

**Idle**
- Brief explanatory line ("Point your camera at text to translate it").
- Primary button: **Take photo**. Secondary: **Choose from library**.
- The target-language selector is visible and editable here too, so the user can set it before shooting.

**Captured / Processing**
- Show the captured image immediately at the top (don't wait for the server).
- Below it, a loading state with a specific label ("Reading text…" then "Translating…" if you can distinguish the phases).
- Allow cancel; cancelling aborts the request and returns to idle.

**Result**
- **Image on top**: aspect-fit, rounded corners, capped at roughly 35–40% of screen height, rendered with `expo-image`.
- **Directly underneath**, a results card containing:
  - The **translated text** as the visual hero — largest type, highest contrast.
  - The **detected original text** in a secondary/collapsible section labeled "Original", smaller and dimmer.
  - The target-language selector, reusing the existing picker component so changing it re-translates the already-detected text **without re-running OCR** (cache `detectedText` in state and call the existing text-translation path).
  - Actions row: **Copy translation**, **Retake**, **Save to history**. Add `expo-haptics` feedback on copy and on successful capture, matching how the rest of the app uses haptics.
- Scrollable, and safe-area aware via `react-native-safe-area-context`.

**Error / empty**
- "No text found in that photo" with a Retake button when `reason === 'no_text_found'`.
- Network/server failures: short human message plus a Retry that re-sends the same image without making the user re-shoot.

### 5c. Image handling before upload

- After capture, run through `expo-image-manipulator`: resize so the long edge is at most **1600px**, output JPEG at **quality 0.7**, request base64.
- Request `base64` from the manipulator, not from ImagePicker at full resolution — full-res base64 will blow up memory and request size on device.

### 5d. Data layer

- Wrap the call in a `@tanstack/react-query` **mutation**, placed in a hook such as `hooks/useSnapshotTranslate.ts`, following the existing hook conventions.
- Validate the response with zod before using it.
- Route the request through `@workspace/api-client-react` if that's how the app's other requests are made — don't hand-roll a `fetch` if a client wrapper exists.
